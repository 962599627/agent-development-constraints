# 开发约束库

> 本文件是**唯一需要 AI 读取**的约束产物。其余文件都是"如何维护它"的流程说明。
>
> **维护铁律**：L0 区不超过 15 条。超了就必须合并或降级 —— 约束一旦膨胀，
> AI 会开始忽略它们，届时不写反而更诚实。

---

## 怎么读这份文件

每条规则包含四个部分，**缺一不可**：

| 字段 | 作用 | 没有它会怎样 |
|---|---|---|
| **规则** | 一句话的可执行约束 | 变成"注意安全"式的废话 |
| **触发** | 什么时候该想起来 | AI 想不起来，等于不存在 |
| **检查** | 怎么验证有没有违反 | 无法自动化，只能靠自觉 |
| **证据** | 哪次真实踩坑换来的 | 后人不知道轻重，容易删掉 |

## L0 · 铁律

> 跨项目通用、违反代价高、**必须有自动化检查方法**。
> 上限 15 条。新增一条就要考虑踢掉一条。

### R-001 凭据绝不硬编码
- **规则**：密钥、密码、token 只能从环境变量/密钥管理读取，**绝不写进源码、文档、配置模板**
- **触发**：新建配置文件、连接数据库、写部署脚本、建 `.env.example`
- **检查**：在源码里搜字面量形式的密码赋值：
  `(PASSWORD|SECRET|TOKEN|KEY)\s*[:=]\s*["'][^"']{6,}["']`
- **证据**：2026-04-25 三处明文密码（`settings.py` / `docker-compose.yml` / `项目大纲.md`）随首次提交进入 git 历史
- **代价**：凭据泄露；补救要轮换密码 + 重写 git 历史

### R-002 忽略规则防不住"已经写进去的值"
- **规则**：`.gitignore` 只能防未来新增的文件。**判断一个文件是否安全，要看内容里有没有值，而不是看文件名是否被忽略**
- **触发**：配置 `.gitignore`、准备首次提交、准备开源
- **检查**：`git grep -n -I -E '<敏感值>' HEAD` —— **直接在当前提交内容里搜**
- **证据**：R-001 同一次事故 —— `.gitignore` 排除了 `.env`，但密码本来就在 `settings.py` 里
- **说明**：这条与 R-001 互补：R-001 防"写"，R-002 防"以为没写"

### R-003 全局副作用必须带测试开关
- **规则**：任何**跨请求共享状态**的机制（限流计数、缓存、单例、连接池、全局标记），
  必须提供一句话就能关闭的开关，否则它会污染测试
- **触发**：新增限流/缓存/熔断/全局状态
- **检查**：跑完整测试套件，看是否出现"单独跑通过、一起跑失败"的用例
- **证据**：2026-04-25 加登录限流（10 次/分钟）后，因所有用例共用缓存计数，
  **整个套件炸出 37 个错误**；第 11 个之后的用例全被 429 挡住
- **修法参考**：`settings` 里用 `sys.argv` 判断测试环境默认关闭，需要验证限流的用例自己打开

### R-004 显示名与标识必须分开
- **规则**：对外展示用一个可变字段（昵称），**路由、查询、身份判断必须用不可变标识（ID）**
- **触发**：任何"跳转到某人主页""查某人的数据""判断是不是本人""按名字查询"
- **检查**：grep 路由与查询串里是否出现 `username` / `name` 之类可变字段
- **证据**：2026-04-25 主页 URL 用用户名暴露账号；团队逐处核对时需要专门列一张表区分两类用法
- **典型翻车**：身份判断写成 `当前用户.用户名 === URL里的用户名` → 一旦 URL 换成 ID，**本人主页会被判定为"他人"**，编辑按钮全部消失

### R-005 HTML 结构必须合法（列表项里别塞按钮）
- **规则**：可点击的整行 + 行内按钮，必须是**兄弟节点**，不能嵌套成 `<a><button>` 或 `<a><a>`
- **触发**：列表项既要整行跳转、又要放操作按钮
- **检查**：检查渲染出的 DOM 是否有 `<a>` 嵌套交互元素
- **证据**：2026-04-25 关注列表加按钮时，`<a><button></button></a>` 导致 HTML 非法 + 点按钮误跳转
- **修法参考**：外层改为 flex 容器，链接 `flex-grow-1` 占左侧，按钮作为兄弟放右侧

### R-006 用户可控的查询参数必须在视图层校验类型
- **规则**：请求参数直接进 ORM 过滤/类型转换前，必须先安全转换，非法值回退默认分支
- **触发**：写列表接口的过滤、分页、排序参数
- **检查**：手工构造非法值请求（`?id=abc`、`?page=1.5`、空值），确认**不是 500**
- **证据**：2026-04-25 `?follower=abc` 直接被 `filter(follower_id='abc')` 抛 ValueError → **500**；
  前端加了守卫也没用 —— 攻击者改 URL 就能绕过前端
- **要点**：前端的校验是体验，**后端的校验才是防线**

### R-007 公开接口默认不返回隐私字段
- **规则**：任何**未登录可访问**的接口，其嵌套的用户对象默认只给 `id` + 展示名；
  邮箱、账号、内部标记（`is_staff`）、私人设置必须**显式**才给，且只在本人视角给
- **触发**：新增公开列表接口、或往公开接口里嵌用户对象
- **检查**：未登录请求该接口，逐字段核对返回内容
- **证据**：2026-04-25 `/api/profiles/` 未登录即可拉取**全部用户的邮箱与账号**，
  连用户自己的"是否公开邮箱"开关都被绕过

### R-008 热重载不可用时，改动后必须重启
- **规则**：服务以"关闭热重载"方式运行时（`--noreload` 等），**代码改动不会自动生效**，
  必须重启进程再验证
- **触发**：启动服务、改完代码准备验证
- **检查**：改一行代码 → 看进程 PID 是否变化 / 行为是否更新
- **证据**：2026-04-25 多次出现"改完没生效"，浪费排查时间；且提权实例无法用常规方式结束进程，
  要用 WMI `Invoke-CimMethod -MethodName Terminate`

### R-009 测试失败要区分"真的坏了"和"被污染了"
- **规则**：一次改动导致**大批**用例失败（尤其报错集中在认证/限流/连接）时，
  先怀疑**共享状态污染**，而不是逐个改用例
- **触发**：跑完整套件出现大面积非预期失败
- **检查**：单独跑失败用例是否通过 → 是的话基本确认是污染
- **证据**：R-003 的 37 个错误；正确修法是让全局机制可关闭，而不是去改 37 个用例

### R-010 入口缺失会让隐藏 bug 永远藏住
- **规则**：数据已经有、但**没有入口能看到**时，视为功能未完成 —— 因为错误无法被发现
- **触发**：做统计数字、计数、状态展示
- **检查**：每个展示出来的数字，问一句"点进去能看到明细吗"
- **证据**：2026-04-25 粉丝列表接口恒返回 0（`?followed=` 被 `follower=me` 过滤吃掉），
  但主页数字是对的，**藏了很久没人发现**；直到做了可点击弹窗才暴露
- **附带收益**：补入口之后，应同步加一条**一致性测试**（列表条数必须等于计数）

### R-011 两个地方说同一件事，就必须有一致性测试
- **规则**：同一个事实被两处呈现（列表条数 vs 计数字段、缓存值 vs 源数据）时，
  必须有一条断言它们相等的测试
- **触发**：实现统计/计数/摘要类字段
- **检查**：检查测试里有没有"两处结果对比"的断言
- **证据**：R-010 同一次 —— 加上"粉丝列表条数 == profile 的 followers_count"这条断言后，
  这类"各说各话"的问题再也藏不住

### R-012 非法/异常路径要有测试，不能只测happy path
- **规则**：新增接口至少覆盖：非法参数、空值、越权访问、边界值
- **触发**：写新接口或新页面
- **检查**：看测试用例里"预期失败"的比例
- **证据**：2026-04-25 R-006 的 500、R-007 的泄露，都是**只测了正常路径**才会漏

## L1 · 协作约定

> 人和 AI、AI 和 AI 之间的协作规则。违反不致命，但会显著降低效率。

### C-001 并行写手的工作范围必须互斥
- **规则**：派发并行任务时，每个执行者的**写入文件集合必须不重叠**；重叠时必须排队
- **触发**：拆分任务、派多个执行者
- **检查**：把各任务的写入路径列出来，检查交集
- **证据**：2026-04-25 多个任务期间出现"文件被并发改写、行号漂移"，
  执行者需要重新 grep 确认自己的改动还在

### C-002 交接信息要带证据，不要只说"已完成"
- **规则**：交付时必须附：命令输出、改动前后对比、未覆盖的情况
- **触发**：任何任务交付
- **检查**：看交付里有没有可直接复现的命令
- **证据**：2026-04-25 多位执行者主动附了 `type-check` 输出与 grep 复核结果，
  使验收成本大幅下降；反之"已完成"三个字无法验收

### C-003 执行者要敢于报告"你给的契约不完整"
- **规则**：发现上游给的接口/约定有缺口时，**先按契约实现，同时明确报告缺口与建议**
- **触发**：实现过程中发现契约缺字段/缺参数
- **检查**：—
- **证据**：2026-04-25 执行者发现 `FollowViewSet` 缺 `?follower=`，
  按契约做完并加了如实提示，同时报告建议 —— 上游随后补上，避免了"数字是别人的、列表是我的"

### C-004 记录要沉淀成规则，不能只写故事
- **规则**：写完一篇开发记录后，问一句"**这里有没有可以变成下次自动生效的约束**"；
  有就提炼到本文件
- **触发**：完成一个功能、修完一个 bug
- **检查**：本文件最近一次更新是否晚于最新开发记录
- **证据**：本项目开发记录已 538 行，但约束区长期只有 2 条 —— 教训没生效，才会重复踩

### C-005 面向人的命令不要有长等待循环
- **规则**：给别人（用户/同事）跑的命令，**单次执行不应可能等待超过约 30 秒**；
  需要重试或耗时操作就**丢到后台**，并明确告知"在跑，出结果通知你"
- **触发**：写脚本、跑网络操作、批量任务
- **检查**：命令里是否有 `Start-Sleep` / 重试循环 / 可能阻塞几十秒的调用
  （如 `Test-NetConnection` 默认要等 20 秒以上）
- **证据**：2026-04-25 推送仓库时写了「重试 6 次 × 每次 sleep 10 秒」的循环，
  网络不稳时长达数分钟零输出，被误判为卡死，用户连续追问"卡了吗""卡了"

### C-006 别用"重试 + 长等待"对付网络问题，先分层诊断
- **规则**：网络操作失败时，**先分辨是应用层还是传输层**，再针对性修；
  不要用无脑重试拖延
- **触发**：`git push` / `fetch` / curl 失败
- **检查**：诊断顺序 —— ① `curl --max-time 5` 看 HTTPS 是否通
  ② 通则说明**网络没问题**，问题在客户端传输层（见 L2 的 `http.version`）
  ③ 仍不通再考虑重试或换网络
- **证据**：2026-04-25 `git push` 连续两次报 `Failed to connect ... port 443`，
  但同一时刻 `curl https://github.com` 返回 **200** —— 网络没问题，是 git 在 HTTP/2 上挂起

### C-007 改了结构就要回头改文档
- **规则**：变更**目录结构 / 版本号 / 核心概念**时，必须**同步**更新 README 与相关说明。
  文档里出现的路径必须是**真实存在**的
- **触发**：新增或删除顶层文件、拆分模块、改版本号、重命名概念、调整安装流程
- **检查**：**只查真实的 markdown 链接**（`[text](path)`）是否存在：
  ```bash
  grep -oE '\]\([^)#[:space:]]+\.(md|sh|ps1)\)' README.md \
    | sed -E 's/\]\((.*)\)/\1/' | grep -v '^http' | sort -u \
    | while read -r f; do [ -e "$f" ] || echo "失效链接: $f"; done
  ```
  版本号也要核对：README 里写的版本是否等于 `cat VERSION`

  > ⚠️ **别把代码块里的文件名也拿去检查**。像 `python.md` / `git.md` 这类是
  > **示意路径**（安装后才存在于目标项目，或相对于 `core/`），
  > 用宽松正则会跑出一大堆误报 —— 这条规则**第一次使用时就踩了这个坑**，故修正为只查链接。
- **证据**：agent-constraints（2026-04）README 长期停留在 `0.1.0` ——
  版本号、目录结构、L2 描述**全部过时**，而 0.2 / 0.3 两次迭代都没回头改它；
  读者会照着不存在的路径找文件
- **代价**：文档漂移会让人**照着错的信息操作**，比没有文档更糟

### C-008 每次提交前必须过脱敏检查
- **规则**：任何**可能被他人看到**的输出（公开仓库、共享仓库、日志、截图、issue）
  在产生前都必须过脱敏检查。**这四类一律不得出现**：
  ① 凭据（密码/密钥/token/连接串）
  ② **本地绝对路径**（含本机用户名、目录结构）
  ③ 个人信息（邮箱、手机号、账号）
  ④ 项目专名与内部代号
- **触发**：`git commit` / `git push` / 发布 / 贴日志与截图 / 提交 issue
- **检查**：**做成自动的，别靠记得**
  - 本仓库已提供：`scripts/sanitize-check.ps1`（配 `.sanitize-deny.txt` 黑名单）
  - 已装为 **pre-commit hook**（`scripts/install-hooks.ps1` 一键启用）
  - 没有工具时手工搜：
    ```bash
    git grep -nEi '(password|密码|token|secret)\s*[:=]'
    git grep -nE  '[A-Za-z]:\\Users\\'
    git grep -nE  '1[3-9][0-9]{9}'
    ```
- **证据**：agent-constraints（2026-04）准备公开仓库时发现
  **31 处项目专名**与一个把本地路径 `F:\python2` 写进**文件名**的示例文件 ——
  都是"当时觉得无所谓"留下的
- **⚠️ 关键认知**：脱敏**只在内容被"写进去"的那一刻有效**。
  一旦提交，git 历史里就**永久留下**了（改文件没用，见 **R-002**）——
  所以检查必须发生在**提交之前**，而不是"公开之前"

### C-009 装进别人运行环境的代码，任何失败都只能降级
- **规则**：插件 / 库 / 中间件 / 钩子这类"跑在宿主里"的代码，
  任何一段失败**只允许降级**（功能不可用），**绝不能把宿主拖垮**
- **触发**：写插件入口、注册钩子、实现宿主回调、发布给别人安装的东西
- **检查**：
  1. 初始化入口（`apply()` 之类）**每一段**都包 try/catch
  2. 宿主回调对**畸形输入**一律原样透传，不改写宿主的决定
  3. 不在顶层 import"宿主承诺会提供"的包 —— **承诺不等于装上了**
  4. 交付前在**真实宿主**里加载一次，而不是只跑单测
- **证据**：agent-constraints 自身（2026-10-05）。插件顶层
  `import { defineTool } from '@deepseek-ai/dsh-tools'`，而目标 profile 设了
  `autoInstallPeers: false` → 该包从未被安装 → 模块解析失败 →
  插件加载态 FAILED → **宿主会话直接崩溃**
  （`Cannot read properties of undefined (reading 'kind')`），用户只能手动禁用
- **代价**：用户的工作环境中断；信任受损（"装你的东西把我的应用搞崩了"）
- **独立发现次数**：1（待更多项目验证后考虑升级 L0）

### C-010 假依赖会掩盖真实的环境问题
- **规则**：测试里造的 stub / mock，如果是为了让"本该存在的东西"看起来存在，
  它同时屏蔽了**"它不存在"**这个最该被看到的信息
- **触发**：为了让 import 成功、让测试跑起来而造 stub 时
- **检查**：
  1. 能用真实依赖就用真实的
  2. 必须造 stub 时，**另加一条不用 stub 的用例**，或加静态检查
     （例如"依赖清单里不得出现 `node:` 以外的外部包"）
  3. 每次造 stub 前问一句：**"如果这个东西真的不存在，我的测试会红吗？"**
     —— 如果不会，那这个 stub 正在掩盖问题
- **证据**：同一次事故。插件测试原本自造 `@deepseek-ai/dsh-tools` 的 stub，
  **11 个用例全绿**；而真实环境里没有那个包 → 加载失败、宿主崩溃。
  事后回看：**当时的全绿是有害的** —— 它让人相信"已经验证过了"。
  与 **C-002** 呼应：证据要能支撑结论，**假环境里的绿不算证据**
- **独立发现次数**：1
- **与 R-001 的关系**：R-001 防"**写**"（凭据别硬编码），
  C-008 防"**提交**"（连带路径、身份、项目名一起过筛）。两条互补

## 快速定位 · 按症状查

> **为什么有这个表**：出问题时，你手上拿的是**症状**（报错原文、异常现象），
> 而不是"我现在在写哪个语言"。如果只能按语言分类，你还得多想一步"该翻哪一节"。
>
> **用法**：先在下面找到你的症状 → 直接翻对应文件，**不要通读**。

### 构建 / 命令 / 环境

| 症状 | 很可能的原因 | 详见 |
|---|---|---|
| `Failed to connect ... port 443` 但 `curl` 能通 | git 在 HTTP/2 上挂起 | [`stacks/git.md`](stacks/git.md) |
| 退出码 1，但命令实际成功了 | PowerShell 把 stderr 当错误 | [`stacks/shell.md`](stacks/shell.md) |
| 脚本报语法错误 + 中文乱码（`鏅鸿兘`） | `.ps1` 缺 UTF-8 BOM | [`stacks/shell.md`](stacks/shell.md) |
