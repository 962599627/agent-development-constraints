# 技术栈坑位库（L2）

> **按需加载**：AI 平时只读 [`constraints.md`](../constraints.md)（L0 铁律 + L1 约定 + 症状索引）。
> 只有**命中症状索引**或**明确在改某个技术栈**时，才翻这里对应的文件。
>
> 这样做是为了不让 AI 一次性读完所有细节 —— 上下文是稀缺资源。

## 怎么用

**两个入口**：

1. **带着症状来**（最常见）→ 先查 [`constraints.md`](../constraints.md) 的**「快速定位 · 按症状查」**表，
   表里会告诉你该翻哪个文件
2. **明确在改某个栈** → 直接打开对应文件

## 往这里加内容的规则

**每个坑必须带「症状」** —— 因为查的人是从症状进来的：

```markdown
### <技术> · <一句话坑名>
- **症状**：你会看到什么现象/报错（写成能直接搜到的原文）
- **原因**：为什么会这样
- **修法**：具体怎么做
- **来源**：哪个项目、什么时候踩的（有独立发现次数就写）
```

**没有「症状」的条目不要加** —— 它无法被索引命中，等于不存在。

## 与 L0/L1 的区别

| | L0 / L1 | L2（本目录） |
|---|---|---|
| 内容 | 跨项目通用的模式 | 具体框架/工具的坑 |
| 位置 | `constraints.md`（必读） | 这里（按需读） |
| 换项目 | **保留** | **整组替换** |
| 升级路径 | 已经是铁律 | 同一坑被 **3 个独立项目**踩到 → 抽象成模式，**升级进 L0** |
