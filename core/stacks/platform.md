# 平台 / 数据库 / 容器

## Windows

### Windows · 保留设备名文件让工具链整体失败
- **症状**：`git add` 报 `error: open("...nul")` 且**所有文件都没提交上**；
  或某程序莫名创建了 0 字节的 `nul` / `con` 文件
- **原因**：`nul`/`con`/`aux`/`prn`/`com1-9`/`lpt1-9` 是**保留设备名**，
  普通路径 API 访问不到（会被当成设备），但文件系统里确实存在
- **修法**：
  - 用 `\\?\` 前缀绕过：`[System.IO.File]::Delete('\\?\F:\dir\nul')`
  - **注意**：`Test-Path 'F:\dir\nul'` 会**误报不存在**（被解析成设备），
    要用 `Get-ChildItem` 列目录来判断
- **来源**：二次元博客（2026-04）

### Windows · 提权进程杀不掉
- **症状**：`Stop-Process` / `taskkill` 报拒绝访问，进程仍在跑
- **原因**：目标进程以更高权限运行，当前用户无权终止
- **修法**：用 WMI 终止：
  ```powershell
  $p = Get-CimInstance Win32_Process -Filter "ProcessId=$procId"
  Invoke-CimMethod -InputObject $p -MethodName Terminate   # 返回 0 表示成功
  ```
- **来源**：二次元博客（2026-04，后端实例提权运行）

### Windows · 端口占用排查
- **症状**：服务起不来，`Address already in use`
- **修法**：
  ```powershell
  netstat -ano | Select-String ':8000\s.*LISTENING'   # 拿到 PID
  ```
  再按上一条的方法终止
- **来源**：通用经验

### Windows · 沙箱/ACL 导致的文件访问被拒
- **症状**：普通可读的路径突然读不了、写不了，且没有明显权限提示
- **原因**：路径或其**某个上级目录**的 ACL 被改坏
- **修法**：逐级检查 ACL，确认是哪一层断了；不要盲目对整个盘符重置权限
- **来源**：二次元博客（2026-04，遇到 `SetNamedSecurityInfoW` 拒绝）

## MySQL

### MySQL · 时区表为空导致日期函数返回 NULL
- **症状**：`CONVERT_TZ` / 时区相关查询返回 NULL
- **原因**：MySQL 安装后**没有导入时区表**（`mysql.time_zone_name` 为空）
- **修法**：要么导入时区表（`mysql_tzinfo_to_sql`），
  要么**在应用层处理时区**（推荐 —— 不依赖数据库配置）
- **来源**：二次元博客（2026-04，见 python.md 的 TruncDate 那条）

### MySQL · 连接数与字符集
- **症状**：中文乱码，或 `Too many connections`
- **修法**：
  - 字符集统一 `utf8mb4`（含 `OPTIONS: {charset: 'utf8mb4', use_unicode: True}`）
  - 连接数问题先查是否**连接未释放**（尤其长驻进程）
- **来源**：通用经验

## Docker / 部署

### Docker · compose 里写死密码
- **症状**：同 R-001，密码进了版本控制
- **修法**：`MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:?请在 .env 中设置}` ——
  `:?` 语法表示**变量未设置就直接报错**，避免误用弱默认值上线
- **来源**：二次元博客（2026-04）→ 已升级为 **R-001**

### 部署 · 环境变量缺失导致的静默降级
- **症状**：功能"看起来配好了"，实际走的是**兜底分支**（如邮件发到控制台、缓存变空实现）
- **原因**：配置读取失败被 `try/except` 吞掉，或环境变量名写错
- **修法**：配置模块要**显式报错**而不是静默兜底；
  提供 `config_problems()` 之类的自检接口，把"配置是否完整"暴露给使用者
- **来源**：二次元博客（2026-04，邮件设置 UI 显示"配置完整"但实际静默回退）

### 部署 · 首次部署后没改默认管理员密码
- **症状**：`admin/admin` 这类默认凭据在生产环境可用
- **修法**：首次部署**立即改**；把这件事写进部署清单，并在文档里注明（但**不要**把密码写进文档）
- **来源**：二次元博客（2026-04，`项目大纲.md` 里曾记录明文管理员密码）

## Redis / 缓存

### 缓存 · 测试时共享缓存污染用例
- **症状**：见 python.md 的「跑测试时限流计数互相污染」——根因相同
- **修法**：任何跨请求共享状态的机制都要有**测试关闭开关**；见 **R-003**
- **来源**：二次元博客（2026-04）

### 缓存 · DEBUG 模式下缓存后端是 DummyCache
- **症状**：限流/缓存**完全不生效**（怎么试都不触发），因为 DEBUG 下用了空实现
- **原因**：很多模板在 `DEBUG=True` 时切到 `DummyCache` 或 `LocMemCache`
- **修法**：确认测试/开发环境的缓存后端**支持你要验证的行为**
  （`DummyCache` 什么都不存，`LocMemCache` 是进程内共享的）
- **来源**：二次元博客（2026-04，限流一直不触发，实为 `DummyCache`）
