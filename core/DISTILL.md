# 提炼流程（DISTILL）

> 目标：把**原始记录**里的教训，变成 `constraints.md` 里**可执行**的规则。
>
> 原则：**宁可少提炼，不要乱提炼**。一条烂规则会让整个规则库被忽略。

---

## 什么时候提炼

- 修完一个 bug（尤其是"排查花的时间远超修复时间"的那种）
- 完成一个功能（尤其是需要跨模块配合的）
- 一次用户反馈驱动的返工
- 一次安全事故或险情（**这类必须提炼**）

## 提炼四步

### 第 1 步：收集原始材料

| 来源 | 怎么取 |
|---|---|
| 会话记录 | 本次开发中：报错信息、走过的弯路、最后的修法 |
| 开发记录 md | 项目里 `job.md` 这类文件的新增条目 |
| 用户反馈 | "这里不对"背后的**根因**，不是表面现象 |

### 第 2 步：筛选 —— 什么才配变成规则

一条原始信息要成为规则，必须**同时**满足：

| 判据 | 说明 | 反例 |
|---|---|---|
| **可复用** | 换个功能/换个项目还会遇到 | "把 `Profile.vue` 第 762 行改成 ID" ← 太具体 |
| **可执行** | 能写成"什么时候 + 做什么 + 怎么查" | "注意代码质量" ← 无法执行 |
| **有代价** | 违反了会有真实损失（时间/安全/数据） | "变量名用驼峰" ← 风格问题，写进 linter 即可 |
| **非显然** | 不是常识、不是看一眼代码就知道 | "要用 `npm run build` 构建" ← 常识 |

**最常见的错误**：把"某次怎么改的"当成规则。规则要回答的是**下次怎么不再犯**。

### 第 3 步：抽象 —— 从个案到模式

这是提炼的**核心动作**。逐层往上抽：

```
个案：改完 Django 代码没生效，因为是 --noreload 启动的
  ↓ 抽象一层
技术：Django 关闭热重载时改动不生效
  ↓ 再抽一层（去掉框架）
模式：热重载不可用时，改动后必须重启进程再验证
```

**抽到哪一层？** 看这条规则**打算跨多大范围复用**：
- 只在这个项目用 → 停在技术层，放进 L2
- 想跨项目用 → 抽到模式层，放进 L0

### 第 4 步：立卡 —— 四要素缺一不可

用 [`templates/rule.md`](templates/rule.md)，四个字段全填：

```markdown
### R-0XX 一句话规则名
- **规则**：可执行的约束（必须有明确的"做什么/不做什么"）
- **触发**：什么时候该想起来（写清单，越具体越好）
- **检查**：怎么验证（**命令、grep、断言** —— 不是"人工review"）
- **证据**：哪次真实踩坑、代价是什么
```

**检查项写不出来的规则，就不要收** —— 说明它还没被想清楚。

## 可直接使用的提炼提示词

把下面这段连同原始材料一起给 AI：

```text
你是一个开发约束提炼器。下面是我的开发记录/会话片段。

请提炼出**可复用**的开发约束，严格遵守：

1. 每条规则必须包含四个字段，缺一不可：
   - 规则：一句话可执行的约束
   - 触发：什么时候该想起来（具体到"写什么代码时"）
   - 检查：怎么验证（给出命令/grep/断言的思路，不要写"人工检查"）
   - 证据：对应的原始记录片段（引用原文）

2. 只收满足全部四条的信息：可复用、可执行、有代价、非显然。
   把"某次具体怎么改的"排除掉 —— 那是记录，不是约束。

3. 先抽象再入库：把个案往上抽一层，写成模式。
   如果这条只适用于某个技术栈，标注出来。

4. 输出前自检：
   - 有没有"注意…""尽量…"这类无法执行的表述？有就删掉
   - 两条规则是不是在说同一件事？是就合并
   - 有没有和现有规则冲突的？有就指出来

5. 最后额外输出一节「本次未收录」，列出你排除掉的信息及原因。
```

> 第 5 点很重要：**被排除的东西要留痕**，否则下次会有人重新提出同样的建议。

---

## 收录后必须做

1. **更新 `constraints.md` 的变更日志**（日期 / 变更 / 触发）
2. **跑一遍 [`PRUNE.md`](PRUNE.md)** —— 检查 L0 是否超限
3. 如果新规则对应一条可执行的检查，**把它写进项目的测试或 CI** —— 规则只有能自动验证才真正生效
