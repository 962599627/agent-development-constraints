# 规则模板

> 复制下面这段填。**四个字段缺一不可** —— 填不出来的话，说明这条规则还没想清楚，先别收。

```markdown
### R-0XX 一句话规则名（动宾结构，如"凭据绝不硬编码"）

- **规则**：可执行的约束。写清"做什么 / 不做什么"，禁止出现"注意""尽量""建议"这类无法判断是否违反的措辞

- **触发**：什么时候该想起来。列成清单，越具体越好（"新建配置文件时""写列表接口的过滤参数时"）
  - 场景 1
  - 场景 2

- **检查**：怎么验证有没有违反。必须是**一条命令 / 一条 grep / 一条断言**，不要写"人工 review"
  - 命令：
  - 或断言：

- **证据**：哪次真实踩坑换来的 + 代价。**这一项是防止后人误删的关键，不要省**
  - 时间：
  - 经过：
  - 代价：

- **修法参考**（可选）：正确的做法长什么样
```

---

## 字段速查

| 字段 | 一句话 | 常见的写坏方式 |
|---|---|---|
| 规则 | **做什么/不做什么** | "注意安全" ← 无法判断 |
| 触发 | **什么时候想起来** | "开发时" ← 太宽泛，等于没有 |
| 检查 | **怎么抓出来** | "仔细检查" ← 不可执行 |
| 证据 | **为什么信它** | 省略 ← 后人会当废纸删掉 |

## 自检

一条规则写完后，问自己：

- [ ] 换个项目、换个功能，这条还成立吗？（不成立 → 降级到 L2 或改写）
- [ ] 有没有和已有规则说同一件事？（有 → 合并）
- [ ] 「检查」能不能写成一条命令？（不能 → 再想想，或降级）
- [ ] 违反它会有**真实代价**吗？（没有 → 不该占 L0 名额）
- [ ] 这条是"某次怎么改的"，还是"下次怎么不再犯"？（前者是记录，不是规则）
