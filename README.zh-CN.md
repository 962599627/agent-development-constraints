# 智能体开发约束包

[English](README.md) | **中文**

一套**会自我进化**的开发约束系统：把开发中踩过的坑，自动沉淀成下次生效的规则。

**当前版本**：0.4.0 · [变更日志](CHANGELOG.md)

---

## 它解决什么问题

大多数项目都有开发记录，但**记录 ≠ 约束**。典型症状：

```
job.md 写了 538 行开发记录
└── 但"必须遵守"区只有 2 条
```

于是同样的坑反复踩 —— **教训只被"记录"了，没被"执行"**。

本包打通「记录 → 规则 → 生效」这条链路，**并防止规则库自己膨胀成没人读的文档**。

## 快速开始

### 安装到项目

```powershell
# Windows
.\install.ps1 F:\my-project
```

```bash
# Linux / macOS
./install.sh /path/to/project
```

脚本是**幂等**的：

| 文件 | 重复安装时的行为 |
|---|---|
| `core/constraints.md`（你的规则库） | **保留不覆盖** —— 这是你积累的资产 |
| `core/DISTILL.md` / `PRUNE.md` / `MERGE.md`、`core/stacks/` | 更新（随包升级） |
| `templates/` | 更新 |
| `AGENTS.md` 的引用段 | 原地刷新（靠 HTML 标记定位，不会重复追加） |

> 想连规则库一起覆盖加 `--force`（先备份）。不想改 `AGENTS.md` 加 `--skip-agents`。

### 安装后做三件事

1. **打开 `agent-constraints/core/constraints.md`**，删掉不适用的条目 ——
   尤其看看**「快速定位 · 按症状查」**表，那是出问题时的入口
2. **打开 `agent-constraints/core/stacks/`** —— 技术栈坑位库
   （`python` / `javascript` / `shell` / `git` / `platform`），整组替换成你自己的栈
3. **把规则库纳入版本管理**，它会随项目一起进化

### 日常使用（关键）

```
开发完成 / 修完 bug
   ↓
问一句：这次有没有可以变成"下次自动生效"的约束？
   ↓ 有                                   ↓ 没有
跑 core/DISTILL.md 的流程提炼              结束
   ↓
跑 core/PRUNE.md 检查是否超限
   ↓
更新 constraints.md + 变更日志
```

## 快速定位 · 按症状查

规则库开头就是**症状索引** —— 因为出问题时，你手上拿的是**报错原文**，
不是"我现在在写哪个语言"。按语言找还得多想一步，按症状是直接命中：

| 症状 | 很可能的原因 | 详见 |
|---|---|---|
| `Failed to connect ... port 443` 但 `curl` 能通 | git 在 HTTP/2 上挂起 | `stacks/git.md` |
| 退出码 1，但命令实际成功了 | PowerShell 把 stderr 当错误 | `stacks/shell.md` |
| 脚本报语法错误 + 中文乱码（`鏅鸿兘`） | `.ps1` 缺 UTF-8 BOM | `stacks/shell.md` |
| **单独跑通过、放进整套就失败** | 共享状态（限流/缓存）污染 | **R-003 / R-009** |
| **本人主页看不到"编辑"按钮** | 身份判断用了可变的展示名 | **R-004** |
| 点行内按钮**误触发跳转** | `<a>` 里嵌了 `<button>`（非法 HTML） | **R-005** |
| **两处数字对不上** | 缺一致性测试 | **R-011** |

分四组：构建/命令/环境 · 测试 · 接口/数据/安全 · 界面/交互。

## 规则库的四层结构

| 层 | 内容 | 上限 | 换项目时 |
|---|---|---|---|
| **L0 铁律** | 跨项目通用、代价高、**有自动化检查** | **15 条** | 保留 |
| **L1 协作约定** | 人机 / 机机协作规则 | 无 | 保留 |
| **L2 技术栈坑位库** | 具体框架的坑 | 无 | **整组替换**（`core/stacks/`） |
| **L3 归档** | 已失效的保留名字 | 无 | 保留 |

**L0 的 15 条上限是硬约束** —— 约束的价值随长度递减，超了 AI 就开始忽略它们，
而被忽略的规则库比没有更糟。

## 每条规则的四要素

```markdown
### R-0XX 一句话规则名（动宾结构）
- **规则**：可执行的约束（禁止"注意…""尽量…"这类无法判断是否违反的表述）
- **触发**：什么时候该想起来（列清单，越具体越好）
- **检查**：怎么验证（**必须是一条命令 / grep / 断言**，不是"人工 review"）
- **证据**：哪次真实踩坑换来的 + 代价
```

**为什么四个都要**：

| 缺了哪个 | 后果 |
|---|---|
| 规则 | 变成"注意安全"式的废话 |
| 触发 | AI 想不起来，等于不存在 |
| 检查 | 只能靠自觉，无法验证 |
| 证据 | 后人不知道轻重，精简时会当废纸删掉 |

**判据**：一条规则写完后，能写出一条**断言**或一条**命令**来抓违反吗？不能的话，它还没被想清楚。

## 为什么用的人越多它越厉害

这是本包的**核心机制**，不是口号。

**问题**：如果只在单个项目内闭环，每个项目各自积累规则、彼此不知道 ——
**人多不产生任何额外价值**。

**解法：独立发现次数（independent sightings）**

一条规则的**可信度**，由「有多少个项目**各自独立**踩到同一个坑」决定：

| 独立发现次数 | 层级 |
|---|---|
| 1 | L2 技术栈 / 项目内 |
| 2 | L1 协作约定 |
| **≥ 3** | **L0 铁律** |
| 被 ≥2 个项目证伪 | 降级 / 归档 |

**为什么有效**：不是投票，是**独立复现**。一条规则在一个项目出现可能是个例；
在**三个独立项目**出现，说明它命中的是**普遍的人性或工具链缺陷**。

**数据怎么流动**：

```
主仓库（精华规则）
   ↓ install
项目 A / B / C 各自积累踩坑经验
   ↓ contribute（靠安装时的基线，自动识别你的新增）
贡献包 → 维护者按 MERGE.md 合并
   ↓ 抽象 + 独立发现次数 +1
主仓库更新 → 再分发给所有人
```

**合并时的「抽象」是关键动作**：

```
候选 A：Django 的 settings.py 里别写数据库密码
候选 B：Node 的 docker-compose.yml 里别写密码
候选 C：文档里别记管理员密码
        ↓ 抽象成上位规则（覆盖三种场景）
R-001 凭据绝不硬编码（源码 / 配置 / 文档 / 模板 全都不行）    独立发现：3
```

**副产品**：规则里的「来源」字段让规则**抗删** ——
有 3 个来源的规则，没人在精简时敢随便删掉它。

详见 [`core/MERGE.md`](core/MERGE.md)（维护者流程）与 [`CONTRIBUTING.md`](CONTRIBUTING.md)（贡献指南）。

## 设计理念

| 决策 | 理由 |
|---|---|
| 规则必须可执行 | 无法判断是否违反的规则等于没有 |
| 必须留证据 | 证据是规则抗删的唯一依据 |
| L0 设硬上限 | 短而准 > 长而全；宁可只留 10 条被遵守的 |
| 只删被工具链替代的 | 归档成本极低，重新发现同一个坑的成本很高 |
| 「本次未收录」要留痕 | 否则下次会有人重新提出同样的建议 |
| 安装幂等 | 用户的规则库是资产，升级流程不能动它 |
| 记录模板末尾带勾选项 | 开发记录最常见的失效方式是"写完没人回头看" |
| 技术栈坑位按需加载 | 上下文是稀缺资源，库一膨胀就会被整体忽略 |

## 与开发记录的关系

本包**不替代**开发记录，而是它的下游：

```
原始记录（会话 / job.md）      ← 又长又碎，人看，AI 不全读
        ↓ DISTILL
约束库（constraints.md）       ← 短、准、可执行，AI 每次必读
        ↓ PRUNE
稳定精华                       ← 长期稳定，新项目直接复用
```

**判断一条信息该放哪**：
- 只有**考古价值**（想回顾当时怎么做的）→ 留在开发记录里
- **下次还会用上** → 提炼成规则

## 贡献

最有价值的贡献是：**「我独立踩到了你库里已有的某个坑」** ——
它会给那条规则 +1 独立发现次数，可能把它从 L1 提升到 L0。

详见 [`CONTRIBUTING.md`](CONTRIBUTING.md)，或在你的项目里跑
`contribute.ps1` / `contribute.sh` 自动提取你新增的规则。
